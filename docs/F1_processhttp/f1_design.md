# F1. HTTP 처리 설계

## 목적과 현재 상태

기존 `src/main.c`의 `socket → bind → listen → accept → close` 흐름에 HTTP 기능을 작은 단계로 추가한다. 기존 코드와 주석을 유지하고 각 단계의 동작을 설명한다.

이 문서는 설계 단계다. HTTP 구현은 롤백된 상태이며 이번 작업에서는 코드를 수정하지 않는다. 이전 논의의 상세 참고 자료는 [F1_processhttp.md](../F1_processhttp.md)다. 참고 자료에 있는 구현 방법 제안을 모두 확정 사항으로 취급하지 않는다.

## 합의한 동작

- 수신 버퍼는 응답 처리 완료까지 유지하고 연결 정리 시 해제한다. 중간 flush나 버퍼 압축은 하지 않는다.
- GET에도 Content-Length가 있으면 그 길이의 본문 수신까지 기다린다. 본문은 정적 파일 응답에 사용하지 않는다.
- 요청의 소비 범위는 헤더 끝 위치 + Content-Length다. read가 후속 바이트까지 반환해도 현재 요청에 포함하지 않고, 연결 종료 시 함께 버린다.

- 수신 버퍼는 4 KiB로 시작해 필요할 때 확장한다. 요청 라인 8 KiB, 전체 헤더(요청 라인 포함) 32 KiB, 본문 1 MiB를 상한으로 둔다.

- F1은 HTTP/1.1 GET 정적 파일 응답까지 구현한다. POST 처리는 이후로 미룬다. 다른 메서드는 405와 Allow: GET으로 응답한다.
- 연결당 첫 요청만 처리하고 Connection: close로 응답한 뒤 연결을 닫는다. 후속 요청은 처리하지 않는다.
- 구현·검증·커밋 단위는 A: HTTP request 파싱, B: HTTP response 생성·쓰기로 나눈다.


- 수신 버퍼와 파서를 분리한다. 수신 데이터를 누적하고 수신 직후 파서에 전달한다.
- 파서는 `추가 데이터 필요 / 완료 / 오류`를 구분한다. 요청 처리 중에는 버퍼를 유지하고 처리 후 정리한다.
- 요청 라인에서 메서드, 요청 대상, HTTP 버전을 추출한다.
- 행은 CRLF, 헤더 끝은 CRLF 두 개로 구분한다. 헤더 끝을 요청 전체의 끝으로 취급하지 않는다.
- 본문은 Content-Length 바이트만큼 처리한다. 본문에는 NUL 바이트와 CRLF가 들어갈 수 있다.
- 경로는 쿼리 분리 → 한 번 디코딩 → 검증 순서로 처리한다. 전체 하위 경로를 유지한다.
- 정적 루트 밖 접근과 중간 디렉토리를 포함한 심볼릭 링크를 차단한다.
- 우선 정적 파일을 대상으로 한다. CGI와 프록시 라우팅은 이후 추가한다.
- 응답 MIME 타입은 실제 제공할 파일의 확장자로 결정한다.
- 상태 라인과 헤더를 한 버퍼에 구성하고 빈 줄 뒤에 본문을 전송한다. Content-Length는 본문의 바이트 수다.
- 부분 읽기·쓰기를 처리하고 EINTR로 중단된 I/O는 재시도한다. 종료 의도가 있으면 정리한다.
- 응답 시작 전 실패는 오류 응답으로 처리한다. 응답 도중 실패는 새 오류 응답을 덧붙이지 않고 정리한다.
- 연결 FD, 열린 파일 FD, 동적 할당 버퍼를 모든 종료 경로에서 정리한다.

## 시간 정책

| 항목 | 합의한 시간 | 기한 기준 |
|---|---:|---|
| 헤더 수신 전체 | 5초 | 연결 수락부터 |
| 본문 수신 전체 | 10초 | 헤더 수신 완료부터 |
| 응답 쓰기 진행 없음 | 5초 | 마지막 실제 전송부터 |

수신 기한은 바이트 도착마다 연장하지 않는다. 시간 정책과 구현 수단을 구분한다.

## 구현 전에 합의할 사항

| 항목 | 기존 제안 또는 선택지 | 결정 시점 |
|---|---|---|
| 시간 제한 수단 | 현재 블로킹 소켓 유지 여부, poll 사용 여부, non-blocking 전환 여부 | 타임아웃 단계 |

미결정 항목은 해당 구현 단계 전에 설명하고 사용자와 합의한다. 지금 한 번에 구현하지 않는다.

## A 구현 결과

- `src/http_request.h`와 `src/http_request.c`에 수신과 파서를 분리했다.
- 파싱 필드는 수신 버퍼의 오프셋·길이로 저장한다. 버퍼 확장 후에도 유효하다.
- 잘못되거나 중복된 Content-Length는 `HTTP_BAD_REQUEST`, 본문 상한 초과는 `HTTP_BODY_TOO_LARGE`로 반환한다.
- Transfer-Encoding 단독은 `HTTP_UNSUPPORTED_TRANSFER`, Content-Length와 병용은 `HTTP_BAD_REQUEST`다.
- 파싱·수신 오류는 HTTP 상태 코드가 아닌 오류 종류로 B에 전달한다.
- HTTP/1.1 요청 라인과 필수 Host의 존재·중복·기본 형식을 검증한다. Host의 상세 문법 검증은 후속 보완 사항이다.
- 파서는 메서드를 추출한다. GET 이외 메서드의 405 응답은 B의 책임이다.
- 기존 블로킹 소켓을 유지한다. 헤더 타임아웃은 아래 보완 내용으로 구현했고, 본문 타임아웃은 남아 있다.
- main은 A 결과를 B에 전달하고, B가 끝난 뒤 버퍼를 해제하고 연결을 닫는다.

## 헤더 수신 타임아웃 보완

- accept 성공 직후 단조 시계로 현재 시간을 기록하고 절대 기한을 5초 뒤로 정한다.
- A의 `http_receive_request()`에 기한을 전달한다. 헤더 수신 중에는 poll에 남은 시간만 전달하며 부분 수신·EINTR로 기한을 연장하지 않는다.
- poll 이후에는 recv의 MSG_DONTWAIT로 해당 호출만 즉시 반환하도록 한다. 소켓 자체를 non-blocking으로 전환하지 않는다.
- 기한 안에 CRLF 두 개까지 수신되지 않으면 HTTP_HEADER_TIMEOUT을 반환한다. B가 이후 408 응답을 담당한다.
- 이번 보완은 헤더 기한만 포함한다. 헤더 완료 이후 본문 수신 10초 제한은 아직 미구현이다.

## B 구현 결과와 확정 정책

- 정적 루트는 실행 디렉토리의 www다. `/`는 index.html로 매핑하고 그 외 디렉토리는 403으로 처리한다.
- 쿼리 분리 → 경로 디코딩 → 검증 후 openat/O_NOFOLLOW로 각 경로 요소를 연다. 중간·최종 심볼릭 링크와 모든 `..` 요소를 차단한다.
- open 시 O_NONBLOCK은 FIFO 등 비정규 파일에서 대기하지 않기 위한 파일 옵션이다. 최종 FD는 fstat으로 일반 파일인지 확인한다.
- MIME은 파일 확장자로 결정한다. HTML/CSS/JS/JSON/PNG/JPG/JPEG 외에는 application/octet-stream이다.
- 요청 오류 400, 접근 차단 403, 파일 없음 404, 비GET 405와 Allow: GET, 헤더 시간 초과 408, 본문 과대 413, 요청 라인 과대 414, 헤더 과대 431, 내부 오류 500, 전송 코딩 미지원 501, 버전 미지원 505를 적용한다.
- 상태 라인·헤더를 한 버퍼로 전송하고 파일을 16 KiB씩 읽어 선언한 길이까지만 전송한다. 작은 송신 버퍼에서도 한 호출이 과도하게 커지지 않도록 send 시도는 최대 1 KiB씩 수행한다. 오류 응답도 길이가 명시된 본문을 가진다.
- 마지막 실제 send 성공 이후 5초간 전송 진전이 없으면 실패를 반환한다. poll과 send(MSG_DONTWAIT)를 사용하며 소켓 모드는 유지한다.
- 응답 중 실패하면 새 오류 응답을 붙이지 않는다. B가 파일 FD를 닫고, main이 수신 버퍼와 연결 FD를 정리한다.
- A에 남은 본문 수신 10초 제한은 이번 B에 포함하지 않았다.
